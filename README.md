# ADMA: weak-link penalisation in agri-food digital maturity assessment

Replication package for the paper

> Kondratiuk, D. (forthcoming), "Benchmarking agri-food digital maturity without masking the weak link", submitted to *Benchmarking: An International Journal*.

The repository contains every statistical input of the paper in its original form, the scripts that compute all reported numbers, and the outputs they produce.

## Two ways to check the results

- **No programming:** open `excel/ADMA_workbook.xlsx`. Every calculation that can be checked by hand is written there as live Excel formulas: an ADMI calculator, Table 7 with all source values and links, Table 6, the worked example, equation (7) and the first 1 000 profiles of the experiment row by row. See its README sheet.
- **Full reproduction:** run the Python scripts below. They reproduce every number of the paper, including the full experiment on 2 x 100 000 profiles.

`scripts/verify_workbook.py` evaluates the workbook formulas with an independent engine and checks 7 159 values against the Python results; they agree exactly.

## Requirements

Python 3.7 or newer and NumPy (tested with Python 3.7.9 and NumPy 1.21.5). Building and verifying the workbook additionally needs `openpyxl` and `pycel` (listed in `requirements.txt`).

```bash
python -m pip install -r requirements.txt
```

`certifi` is optional; install it if downloads fail with an SSL certificate error (common on macOS Python builds).

## Reproducing the paper

Run the scripts from the repository root.

**1. Computational experiment (H1–H3).** About one minute.

```bash
python scripts/simulation_experiment.py
```

Reads the stored profiles in `data/generated/` and writes `results/simulation_experiment.json`. The profiles were generated by `scripts/generate_profiles.py` with seed 2026; regenerating them gives identical files. Mapping to the paper:

| Paper | JSON key |
|---|---|
| Section 4.1, worked example | `worked_example` |
| Table 4, H1 | `scenarios.<scenario>.H1_calibrated`, `H1_initial`, `H1_calibrated_model_adjusted_bounds` |
| Equation (7), boundary band | `boundary_band_calibrated` |
| Table 5, aggregation rules | `scenarios.<scenario>.aggregation_rules` |
| Section 4.4, H2 | `scenarios.<scenario>.H2_integration_masking` |
| Table 6, diagnostic situations | `diagnostic_situations` |
| Section 4.5, H3 | `scenarios.<scenario>.H3_sensitivity` |

**2. Statistics mode on the stored data (Table 7).** Works offline.

```bash
python scripts/statistics_mode_local.py
```

Reads only `data/raw/`, prints Table 7 and writes `results/statistics_mode_local.json`. This reproduces the published values regardless of later revisions by the statistical agencies.

**3. Statistics mode on live data (optional).** Requires internet access.

```bash
python scripts/statistics_mode_api.py
```

Downloads the same series from the Eurostat API and the Derzhstat data bank into `data/api_snapshot/<date>/`, runs the same computation and lists every value that differs from the stored data. Differences are expected over time, because both agencies revise data and add new survey years. On 9 October 2026 the live data reproduced the stored data exactly.

**4. Excel workbook (optional).**

```bash
python scripts/build_workbook.py    # rebuild excel/ADMA_workbook.xlsx
python scripts/verify_workbook.py   # compare its formulas with the Python results (about 30 s)
```

## Level classification at exact ties

Index values computed from questionnaire answers are multiples of 1/120, so a value can fall exactly on a level bound. By the rule of the paper such a value belongs to the lower level. Both implementations round the index to 12 decimals before classification so that floating-point noise cannot move a tie to the upper level.

## Data sources

- Eurostat, *ICT usage in enterprises*, datasets `isoc_eb_iipn2`, `isoc_cicce_usen2`, `isoc_eb_iotn2`, `isoc_cisce_ran2` (DOIs in `data/README.md`).
- State Statistics Service of Ukraine, *Use of information and communication technologies at enterprises*, data bank stat.gov.ua, dataflow `SSSU:DF_INFORM_COMMUN_TECH_ENTRP`.

Indicator definitions in the two surveys are harmonised (Regulation (EU) 2019/2152); the correspondence used in the paper is given in Table 3 and in `scripts/data_sources.py`. See `data/README.md` for reference years, breaks in series and coverage.

## Notes

- The simulation profiles are synthetic. They describe the behaviour of the index over the whole response space, not the state of real enterprises.
- The penalty parameters α = 0.40 and δ = 0.375 come from a separate calibration on a system dynamics model of enterprise digital transformation (Kondratiuk, 2026, doi: 10.70286/ISU-07.10.2026.013). That model is not part of this package.
