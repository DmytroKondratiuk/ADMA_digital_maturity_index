# ADMA: штраф за слабку ланку в оцінюванні цифрової зрілості агропродовольчих підприємств

*English version: [README.md](README.md)*

Пакет для відтворення результатів статті

> Kondratiuk, D. (forthcoming), "Benchmarking agri-food digital maturity without masking the weak link".

Репозиторій містить усі статистичні вхідні дані статті в первинному вигляді, скрипти, що обчислюють усі наведені в ній числа, і результати їхньої роботи.

Документація, Excel-книга та файли результатів доступні англійською та українською мовами; українські файли мають суфікс `_ua` (`README_ua.md`, `excel/ADMA_workbook_ua.xlsx`, `results/*_ua.json`).

## Два способи перевірити результати

- **Без програмування:** відкрийте `excel/ADMA_workbook_ua.xlsx` (англійська версія: `excel/ADMA_workbook.xlsx`). Кожен розрахунок, який можна перевірити вручну, записано там живими формулами Excel: калькулятор ADMI для анкети з 21 твердження, приклад розрахунку, таблиці 5 і 6 з усіма вихідними значеннями та посиланнями, ранжування TOPSIS, таблиця 4, рівняння (7) і перші 1 000 профілів експерименту рядок за рядком. Див. аркуш «Опис».
- **Повне відтворення:** запустіть Python-скрипти, описані нижче. Вони відтворюють усі числа статті, зокрема повний експеримент на 2 x 100 000 профілів.

`scripts/verify_workbook.py` обчислює формули книг незалежним рушієм і перевіряє 7 533 значення кожної книги (англійської та української) з результатами Python; вони точно збігаються.

## Вимоги

Python 3.7 або новіший і NumPy (перевірено на Python 3.7.9 і NumPy 1.21.5). Для побудови та перевірки книги додатково потрібні `openpyxl` і `pycel` (зазначені в `requirements.txt`).

```bash
python -m pip install -r requirements.txt
```

`certifi` необов'язковий; встановіть його, якщо завантаження завершуються помилкою SSL-сертифіката (часто трапляється у збірках Python для macOS).

## Відтворення статті

Запускайте скрипти з кореня репозиторію. Поруч із кожним файлом результатів скрипти записують українську копію `<назва>_ua.json`: ключі та коди в ній ті самі, що в англійському файлі (це ідентифікатори, на які посилається документація), а текстові значення (описи, сила відповідності) - українською.

**1. Обчислювальний експеримент (P1–P3).** Менше хвилини.

```bash
python scripts/simulation_experiment.py
```

Читає збережені профілі з `data/generated/` і записує `results/simulation_experiment.json` (і `results/simulation_experiment_ua.json`). Профілі згенеровано скриптом `scripts/generate_profiles.py` з seed 2026; кожен профіль містить 21 відповідь анкети, а повторна генерація дає ідентичні файли. Відповідність статті:

| Стаття | Ключ JSON |
|---|---|
| Приклад розрахунку на початку розділу 4 | `worked_example` |
| P1, додаткова таблиця S2 | `scenarios.<scenario>.P1_calibrated`, `P1_initial`, `P1_calibrated_model_adjusted_bounds`, `P1_residual_masking` |
| Рівняння (7), гранична смуга, рисунок 2 | `boundary_band_calibrated` |
| Таблиця 3, правила агрегування та перевірка асиметрії | `scenarios.<scenario>.aggregation_rules` |
| P2, ілюзія зрілості | `scenarios.<scenario>.P2_integration_masking` |
| Таблиця 4, діагностичні ситуації, рисунок 3 | `diagnostic_situations` |
| P3, чутливість до alpha і delta | `scenarios.<scenario>.P3_sensitivity` |

Сценарії (`<scenario>`): `uniform` - рівномірний, `low_skewed` - зміщений до низьких відповідей.

**2. Статистичний режим на збережених даних (P4).** Працює офлайн.

```bash
python scripts/statistics_mode_local.py
```

Заново будує матрицю порівняння з `data/raw/eurostat/ict_c10_c12/` і `data/raw/ukrstat/ict_c10_c12/`, перевіряє, що вона ідентична `data/matrix.csv`, друкує таблиці 5 і 6 і записує `results/statistics_mode_local.json` (і `results/statistics_mode_local_ua.json`): оцінки показників, оцінки шарів, ADMI, рівні та ранги (`countries`, `ranking`), порівняння з базовим індексом без штрафу (`spearman_ADMI_base`), порівняння з TOPSIS (`entropy_weights`, `spearman_ADMI_TOPSIS`, `pearson_ADMI_TOPSIS_values`, `spearman_TOPSIS_entropy_vs_equal`) і перевірку стійкості до проксі-показників з додаткової таблиці S3 (`proxy_robustness`). Це відтворює опубліковані значення незалежно від пізніших переглядів даних статистичними відомствами.

**3. Статистичний режим на актуальних даних (необов'язково).** Потребує доступу до інтернету, кілька хвилин.

```bash
python scripts/statistics_mode_api.py
```

Завантажує ті самі зрізи з API Євростату та банку даних Держстату в `data/api_snapshot/<дата>/`, заново будує матрицю, виконує той самий розрахунок і виводить усі значення, що відрізняються від збережених даних. З часом відмінності очікувані, бо обидва відомства переглядають дані й додають нові роки обстеження.

**4. Excel-книга (необов'язково).**

```bash
python scripts/build_workbook.py    # перебудувати excel/ADMA_workbook.xlsx і excel/ADMA_workbook_ua.xlsx
python scripts/verify_workbook.py   # порівняти їхні формули з результатами Python (близько 1 хв)
```

## Визначення рівня при точному збігу з межею

Значення індексу, обчислені з відповідей анкети, кратні 1/60, тому значення може точно припасти на межу рівня. За правилом статті таке значення належить до нижчого рівня. Обидві реалізації округлюють індекс до 12 знаків перед класифікацією, щоб похибка обчислень з плаваючою комою не перенесла такий збіг на вищий рівень.

## Джерела даних

- Євростат, *ICT usage in enterprises* (використання ІКТ на підприємствах), тринадцять наборів даних за видами діяльності NACE Rev. 2 (коди та DOI - у `data/README_ua.md`), харчова промисловість C10–C12, підприємства з 10+ зайнятими.
- Державна служба статистики України, *Використання інформаційно-комунікаційних технологій на підприємствах*, банк даних stat.gov.ua, потік даних `SSSU:DF_INFORM_COMMUN_TECH_ENTRP`, КВЕД 10–12.

Визначення показників у двох обстеженнях гармонізовано (Регламент (ЄС) 2019/2152); відповідність показників твердженням анкети та її сила наведені в додатковій таблиці S1 статті та в `scripts/data_sources.py`. Звітні роки, розриви рядів і охоплення описано в `data/README_ua.md`.

## Примітки

- Профілі симуляції синтетичні. Вони описують поведінку індексу на всьому просторі відповідей, а не стан реальних підприємств.
- Параметри штрафу α = 0,40 і δ = 0,375 отримано окремим калібруванням на системно-динамічній моделі цифрової трансформації підприємства (Kondratiuk, 2026, doi: 10.70286/ISU-07.10.2026.013; модель: doi: 10.5281/zenodo.19979159). Модель працює з оцінками шарів, а не з пунктами анкети, тому калібрування не залежить від кількості тверджень у блоці. Ця модель не входить до пакета.
- Наведені в статті дані на рівні господарств для секції A NACE (робототехніка та точне землеробство) взято безпосередньо з цитованих джерел (Євростат `ef_mp_digi`, Держстат `DF_AGR_MACHINERY_AVAILABILITY`), вони не входять до пакета.
